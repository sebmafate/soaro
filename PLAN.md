## Approach

Soaro is an adopted project: only the **remaining work** is planned (requirements R1 to R19, the accessibility work decided on 2026-11-15, the Docker test and release 1.1). The baseline is the existing suite (135 tests, green); there is no walking skeleton to build.

Order: first what protects the user and the tests that follow (Return never deletes, repository guards), then the shared components the new screen needs, then the tool from the simplest piece to the riskiest: NuGet, a read-only look at iOS simulators (command line, then screen), removal of simulators, then Android (list, then removal, with the two spikes of risks 5 and 6). The accessibility work that nothing depends on (SL4, SL5) comes after the first useful slice, and the Docker part waits for its test.

**First useful slice: SL9** (simulators can be removed). SL6 (NuGet) is an earlier quick win. Deliberately after it: Android, the system images, Docker.

**Time box (kill criterion 3 of the spec):** the Must scope (R1 to R9 and R16 to R18) is capped at **14 working days**. Assumed sizes: S is about 1 day, M about 2 days. The Must slices (SL1, SL2, SL6 to SL11) add up to **13 days**, which leaves 1 day of margin that the two Android spikes may use. **SL3 is not counted** in the cap, and neither are SL4 and SL5 (accessibility decisions of the author, not R1 to R19; confirmed 2026-11-15). If the Must slices pass 14 days, stop and cut to iOS simulators and Android devices only. Days actually spent are written in the table below.

## Slice details

### SL1: Return never deletes

- **Goal**: pressing Return on a confirmation never deletes anything; Cancel is the default button.
- **Serves**: R8 (extended 2026-11-15); `DESIGN.md` accessibility rule "Confirmation default".
- **Components**: `AppState.confirm` and its five callers (cleanup, Trash, inactive projects, uninstall, login items); the cleanup models.
- **Acceptance criteria**
  - [x] The alert is built separately from being shown, and its default button is Cancel for all five callers.
  - [x] The `critical` flag still sets only the alert style.
  - [x] Each cleanup model receives its confirmation as an injectable parameter with a default; a test with a "cancel" confirmation shows that nothing is deleted (inactive projects, large files, uninstaller, login items).
  - [x] The confirmation text of existing tools is unchanged.
- **Tests**: unit (alert configuration; models with an injected confirmation).
- **Notes**: touches published behaviour: a `CHANGELOG` line. Enables the "cancelling deletes nothing" tests of later slices. Done 2026-11-16: `AppState.makeConfirmationAlert` and `AppState.confirmationResult`; the type `ConfirmHandler` and `SystemConfirmation.ask` (in `CleanupModels.swift`); the four models take `confirm:` plus an initial-state parameter (`files`, `artifacts`, `apps`/`current`, `loginItems`; empty by default) as the test seam. The cleanup action of `AppState.cleanup` is not injected (out of scope): it gets the Cancel default through the shared builder only. The login-item test is weak by nature (removal is asynchronous). Still to check by hand: Return then Escape in a real alert (English and French).

### SL2: Repository guards

- **Goal**: two tests that protect the privacy promise and the translations for every later slice.
- **Serves**: R9, R12; `TESTING.md` T6, T11.
- **Components**: the test target only (reads the sources and `Sources/Soaro/Resources/Localizable.xcstrings` through `#filePath`).
- **Acceptance criteria**
  - [x] A test fails if a source file other than `PublicIPService.swift` references `URLSession` or `NWConnection`. (`NetworkAllowlistTests`; made to fail on purpose with a throwaway file, then removed.)
  - [x] A test fails if a catalog key lacks one of the nine languages, or if the placeholders (`%@`, `%lld`, `%1$@`, `%%`) differ between languages. (`TranslationCatalogTests`, on `Localizable.xcstrings` and `InfoPlist.xcstrings`.)
  - [x] Both tests pass on the current code, or the real gaps they find are listed (fixed here if small). (17 gaps found, all in French, all fixed in one commit; see Notes.)
  - [x] Where the defaults of the two optional network features are readable from a test, a test shows they are off. (`OptInDefaultsTests`, registered defaults only.)
- **Tests**: unit (repository level).
- **Notes**: if the catalog test finds existing gaps, list them rather than widening this slice.
  - Gaps found on the real catalog (17, all French): 16 keys had no French entry (`1 h`, `24 h`, `Application`, `CPU`, `GPU`, `Internet`, `Max`, `Min`, `Orange`, `Signal`, `Soaro`, `Style`, `VPN`, `Wi-Fi`, `Xcode iOS DeviceSupport`, `normal`); the French text of the battery explanation wrote `100 %%` where the key has no placeholder, so the app showed `100 %%` (checked on the built bundle). Fixed in one commit: the 16 French entries equal the English key (what the app already displayed through the fallback), and `%%` became `%`. These French strings are AI-assisted and flagged for the author's review.
  - The placeholder rule treats a key without placeholder as never formatted: `100 % zu` in German is not a gap there. Checked for `String(localized:)`; `Text("...")` was not checked.
  - Days spent (0.25): measured from the first to the last SL2 commit timestamp, rounded up to a quarter day.
  - Out of reach of the allowlist: `Data(contentsOf:)`, `Process`/`curl`, `NWPathMonitor`, Sparkle, and the optional `/sbin/ping` of `NetworkSampler.ping`.

  - [x] Demo mode shows the row without touching the disk (`DemoData` has 13.1 GB for NuGet; confirming in demo mode deletes nothing: `CacheCleanupFlowTests`, and in the four tools `DemoModeToolsTests`). Looked at on screen: not done, pending the author.

It differs from before only when a deletion fails partway (an item that fails now adds what was really removed; `removeItem` stops at the first error, in directory order). The on-disk partial-failure test does not depend on the directory order; the strict partial credit is proven with the injected measure.

### SL25: The flag follows a change of public IP faster

- **Goal**: refresh the country flag sooner **when the public IP changes, and not otherwise**. The author's request of 2026-11-18: "faire en sorte que l'icône du pays de l'IP publique se rafraîchisse plus souvent (si l'IP change, sinon pas la peine)". For 1.2.0. **Depends on the SL23 branch** (stacked: it extends the lookup policy and `AppState` work of SL18/SL19). Decision record: **ADR 0012** (extends 0011, does not supersede it).
- **Interpretation applied (overrule if wanted)**: do **not** poll the third-party service more often (the 5-minute fallback stays, no extra traffic when nothing changes); **detect more of the situations in which the public IP can have changed**, look up promptly only then, and once more shortly after (routes settle late).
- **Signals now in the fingerprint** (`NetworkSignals`, a pure value built by a pure function from plain dictionaries; read with SystemConfiguration and `getifaddrs`, no request, no permission): the primary interface and default gateway (IPv4 and IPv6, `State:/Network/Global/IPv4` and `IPv6`); for each network service (`State:/Network/Service/<id>/IPv4`): interface, addresses, router and macOS's own `NetworkSignature` (it contains the router's hardware address: two home networks in 192.168.1.x with the same router address are told apart without the Wi-Fi name); the DNS servers, domain and search domains (`State:/Network/Global/DNS`); the active IPv4 tunnels (utun, ipsec, ppp, tun, tap) with their addresses. The old parts (local IP, VPN on or off, VPN interface, VPN name) are unchanged, and with no signal the fingerprint string is exactly the old one.
- **Signals NOT used**: the Wi-Fi name (SSID) and access point (BSSID). On this Mac (2026-11-18) `State:/Network/Interface/en0/AirPort` gives an empty `SSID_STR` and a BSSID of `02:00:00:00:00:00` (macOS redacts them without the Location permission), CoreWLAN `ssid()` is nil without it, and a permission prompt is out of the question. The BSSID would also change when roaming between access points of one network with no change of public IP. Never read, as noise: signal strength, byte counters, lease times, IPv6 temporary addresses, `AdditionalRoutes`, ARP resolution keys. Tunnels count by IPv4 only (the Apple system tunnels have IPv6 only).
- **Event source: SystemConfiguration dynamic store, not `NWPathMonitor`.** Why: the store notifies exactly the keys the fingerprint reads (including a change of DNS servers or of the gateway or address of a tunnel that keeps its interface, the VPN hop case, which a path monitor does not report: from the API documentation, not tested); it needs no entitlement for a non-sandboxed app (ADR 0002); it is already linked (`MachineInfo.swift`); it plugs into the main run loop, so no dispatch queue and no thread. Watched: the three global keys and `State:/Network/Service/[^/]+/IPv4`, plus `NSWorkspace.didWakeNotification`. `NWPathMonitor` stays allowed by the allowlist test and unused.
- **Constants** (`PublicIPLookupPolicy`): `quietPeriod` 3 s (the debounce: a burst of events is one trigger, and a changed fingerprint must stay the same for 3 s), `settleDelay` 10 s (the confirmation). `firstLookupWaitCap` 10 s (the first flag lookup waits for the VPN detection, see the defect below). Unchanged: `refreshAge` 300 s, `changeGap` 5 s, `steadyGap` 60 s, `failureBackoff` 60 s, `flagMaxAge` 3600 s.
- **Confirmation rule**: after a lookup caused by a detected change (a settled change of fingerprint, or a wake; **not** the first lookup, the periodic one, nor a click on Refresh) exactly one more lookup 10 s later (at the next 3-second measure, so 10 to 13 s). The newer answer is kept; same or different, nothing more. Not after a failure; cancelled when the setting is turned off or the flag hidden; never in demo; respects the 60 s pause after a failure (also with the Network tab open, where only the confirmation is paused: the tab keeps its old rules for everything else). It is in the pure policy (`Inputs.lastChangeTriggeredLookup`, `settleDelay`).
- **Decisions in the code**
  - (a) The monitor (`NetworkChangeMonitor`) only calls back after the calm period; `AppState` then re-reads the VPN (local) and the usual decision function judges. It never calls the lookup service. It exists only while `PublicIPLookupPolicy.monitorWanted` holds (setting on, no demo, network item shown or Network tab open: the same condition as the lookup, tested equal on a grid), is created and cancelled with it (every 3-second measure, every decision and when the setting is turned off), and its callback holds `AppState` weakly (test).
  - (b) **The 3-second measure also waits for the calm period** (`FingerprintSettler`, a pure struct): otherwise it would look up in the middle of a burst, before the monitor's trigger. The Network tab keeps its immediate rule and so does the first lookup. This is the one place where timing differs from before for a change seen by the measure alone, and only for the flag path.
  - (c) A wake forces "changed" once (even if the fingerprint is the same), consumed when a lookup starts.
  - (d) The flag follows the extended fingerprint: after any change the flag is hidden at once (the fingerprint read now differs from the one of the reply) until the new reply arrives.
  - (e) Seams: `AppState.init(networkWatching:)` (a `NetworkWatching` struct: source factory, scheduler, signals reader, VPN detection, clock, log), placed before `announce`; `AppState.vpnRefreshTask` to await the detection.
  - (f) `SOARO_DEBUG=1` writes one line per lookup (`lookup: first|network-change|wake|confirmation|periodic|forced`) and per settled event on the error output: the reason and the time, never the address or the country.
  - (h) **Defect found after delivery, and its fix (the first version of SL25 had it).** The author's real `SOARO_DEBUG=1` log on his Mac, network untouched, showed three lookups within 20 s at every launch: `first`, then `network-change` 6 s later, then `confirmation` 12 s later. **Cause (checked in the code):** `tick()` calls `refreshPublicIPWhileFlagShown`, which starts the VPN detection (`refreshVPN`, asynchronous) and then calls `refreshPublicIP` at once, while `vpn` is still `nil` (`@Published private(set) var vpn: VPNStatus?`). The first lookup is therefore stored with the draft fingerprint `ip|none|-|-`; the detection then returns (the author's Mac has a VPN up: `ip|vpn|utun4|name`), the next measure sees a different fingerprint, it stays the same for the 3 s calm period (so +6 s), and it counts as a real change, which also arms the confirmation (+12 s). - **Decisions**
  - **Whole pixels, per scale.** Body 28 x 13 pt = 28 x 13 px at 1x, 56 x 26 at 2x. Outline 1.2 pt = 1 px at 1x, 2 px at 2x, 4 px at 3x (Increase Contrast adds a pixel or more: 2, 3, 5), gap 1, 2, 2 px, fill in 1 px steps (min 1 pt, full only at 100 %), corner radius 0.3 x height in whole pixels, mark height 1.2 x body height, halo 0.9 pt (1, 2, 3 px): the rules of the label, scaled.
  - **Parity.** A shape centred in a body of N px lands on whole pixels only if its size has the parity of N. The card (13 pt) and the tab (15 pt) bodies are odd at 1x, so the nub height, the mark height and the mark width take the nearest number of the body's parity (`PixelGrid.px(_:scale:parity:)`; for an even body it is `evenPx`, so the menu bar is unchanged). At 1x the card mark is 15 px high (not 16) and the tab one 19 px.
  - **Whole-point image.** The image has the same size in points at every scale: body + nub (nub = 17 % of the height rounded to a whole point: 2 pt on the card, 3 pt on the tab) wide, and a 2 pt margin above and below for the mark, compensated by a negative padding so the layout size is the body height. **Layout change:** the glyph is 30 x 13 pt on the card (was 30.21 x 13) and 35 x 15 on the tab (was 34.55 x 15): under half a point.

Increase Contrast comes from the environment too.

With one path for the halo and the mark, their opposite windings cancelled inside the halo band, so the fill stayed under the mark and the ink doubled (0.56 + 0.56 x 0.44 = 0.80: a darker plug).
